Веб-плагин DSH для **файлов истории сессий + проверки здоровья сессий**.

> **В этой версии (0.5.0) главной линией стала линия DSH 0.2.0** (peer/engines = `>=0.2.0-rc.1 <0.2.1-0`, npm dist-tag `dsh-0.2.0`, ветка `compat/0.2.0`).
> Линию DSH 0.1.7 продолжает обслуживать 0.4.8 (dist-tag `dsh-0.1.7`, ветка `compat/0.1.7`); вместе с настоящей линией она больше не развивается.
> Поверхности хоста, которые потребляет этот плагин (формат сессии V4 и списки first-party-продюсеров `dsh-session-format-v3-to-v4`, экспортируемые декодеры `dsh-session`, контракт каталога архивов `session.jsonl.zstd`/`session.v3.jsonl.zstd` в двух экземплярах + `storages/session_projcache` + два списка id в `workspace.json`), проверены по пунктам: в 0.2.0-rc.1 они **не изменились, нулевые правки кода**; этот релиз — адаптация одних лишь метаданных (смена поколения peer/engines, devDependencies точно закреплены на `0.2.0-rc.1`, дисциплина релизов обновлена вместе с версией).

- **Дом престарелых (файлы истории)**: просмотр официального набора архивов, две **независимые** операции —
  **снять статус архивации** (меняет только массив, обратимо) и **очистить архивные файлы (purge)** (по-настоящему удаляет сущности с диска, необратимо).

> **Эти две операции не взаимозаменяемы, и объединять их нельзя**:
>
> | | Снять статус архивации | Очистить архивные файлы (purge) |
> |---|---|---|
> | Маршрут | `session-history-prune` | `session-history-purge` |
> | Что меняется | только `global.archivedSessionIds` | удаление сущностей с диска + изменение массива архивов + изменение таблицы участников рабочих пространств |
> | Судьба сессии | возвращается в исходное рабочее пространство боковой панели | исчезает из мира |
> | Обратимо | ✅ | ❌ |
>
> **Очистка с необходимостью влечёт снятие статуса архивации** — иначе останутся id-зомби, «невидимые в боковой панели, которые при снятии архивации превращаются в пустую сессию».
> Размер показывается **построчно** (на практике: одна запись может занимать от 0 до 23 МБ), кнопка показывает подытог по выбранным.
>
> **Два жёстких ограничения** (соблюдайте, иначе операция окажется напрасной):
> 1. **Список и запись исходят из одного и того же места** — оба признают файл хранилища `~/.dsh/storages/workspace.json`. Находящийся в памяти хоста `workspaceRegistry` — снимок на момент запуска: правка файла не записывается обратно в него; он служит лишь диагностической поверхностью для «уже удалено из файла, но в этом процессе ещё действует» (`pendingRestart`).
> 2. **Сразу после операции перезапустите DSH** — слой хранилища выполняет полную перезапись, и память имеет приоритет: до завершения работы хоста **любое** изменение архивов или рабочих пространств целиком записывает старое состояние обратно, сводя только что выполненную операцию к нулю.
- **Диспансеризация (проверка здоровья / сессионный врач)**: осмотр по четырём воротам → рецепт (список команд) → выписка (обратимое вмешательство + сравнение до/после).

> Граница именования: **этот пакет не предоставляет поиск и индексацию**. Поиск/отдельная индексация относятся к другому владению (`dsh-search-index`); ни одна из сторон не употребляет поддоменные термины другой и не интерпретирует поля другой.

## Установка

```bash
dsh plugin --profile web add dsh-session-steward
# или локальный каталог разработки
dsh plugin --profile web add "link:E:/test/rewrite-agently/mine-dsh-plugins/dsh-session-steward"
```

После установки **обязательно перезапустите процесс-хост** (обновления страницы недостаточно).

## Контракт маршрутов

Префикс `/session-steward/api`, имена методов всегда `session-*` (**нельзя** смешивать с `index-*` поискового индекса);
нераспознанный метод возвращает явную ошибку, никогда не молчит.

| Метод | Поддомен | Назначение |
|---|---|---|
| `session-history-list` | history | перечислить набор архивов (приоритет у файла хранилища; с указанием источника, деградации, построчного размера и пометки `pendingRestart`) |
| `session-history-prune` | history | **снять статус архивации**: массово убрать id из массива архивов (автоматическая резервная копия, требуется перезапуск) |
| `session-history-purge` | history | **очистить архивные файлы**: по-настоящему удалить каталог транскриптов + кэш проекций + оба списка id (**необратимо**) |
| `session-health-status` | health | состояние переключателей и таблица методов (для опроса панелью) |
| `session-health-scan` | health | пакетная проверка (по умолчанию возвращает только сессии не-ok) |
| `session-health-session` | health | отчёт по четырём воротам одной сессии + рецепт |
| `session-health-repair` | health | обратимое вмешательство (карантин записи кэша проекций) + до/после |

Пространство имён настроек: `session-steward`; id пункта боковой панели: `dsh-session-steward`.

## Два переключателя (feature gate)

| Переключатель | Поле | Эффект выключения |
|---|---|---|
| Файлы истории сессий | `historyFiles` (по умолчанию true) | `session-history-*` не регистрируется, вкладка «Дом престарелых» не рендерится |
| Проверка здоровья | `healthCheck` (по умолчанию true) | `session-health-*` не регистрируется, вкладка «Диспансеризация» не рендерится |

При выключении соответствующий метод возвращает `{ ok: false, error: '子域已关闭（…=false）：<method> 未注册' }` — **пустых оболочек не остаётся**.

## Осмотр по четырём воротам

| gate | Критерий | level |
|---|---|---|
| `log-integrity` | мультифреймовое сканирование zstd → разворачивание provenance → распаковка упакованных строк; seq непрерывны, нет разорванных хвостовых фреймов | `fail` при проблемах чтения; `warn`, если только разорванный хвостовой фрейм |
| `projection-cache` | отставание `minSeq` файла `~/.dsh/storages/session_projcache/sessions/<id>.json` от последнего seq журнала + незакрытые поля (openStep / activeStep.active / pendingTurnStart / turnBoundary=start) | `fail` при отставании и незакрытости; `warn`, если только одно из двух |
| `lossless-json` | построчная проверка JSON на потерях через горячее состояние `sessionProjections.checkpoint(session)` (undefined / не конечные числа / -0 / разреженные дыры / необычный прототип / функции·Symbol·BigInt / циклы) | `fail` при обнаружении, с ключом проекции → пакетом-владельцем |
| `cold-read` | причина последнего `turn/end`, наличие незакрытого open step, есть ли вывод assistant после последнего сообщения user | `fail` при open step; `warn` при interrupted/отсутствии turn/end |

**Рецепт** предлагает только три обратимые вещи: ① поместить повреждённую запись кэша проекций в карантин (сначала резервная копия) ② при наличии незакрытых step напомнить дождаться их закрытия хостом ③ выдать список исполняемых команд.
**Запрещено**: переписывать журналы сессий, менять исторические данные, молча отбрасывать поля.

## Единственный контракт с `dsh-search-index`

Формат файла архива (`global.archivedSessionIds` из `~/.dsh/storages/workspace.json`):
**этот плагин пишет, поисковый индекс только читает**. Описание формата в
`dsh-docs-deliverables/dsh-归档文件格式契约-20260914.md`.
